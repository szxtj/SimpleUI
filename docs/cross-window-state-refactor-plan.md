# 跨窗口状态与「发送 / 停止」重构方案

> 目标：把「两个窗口各持一份状态、互相猜对方在干什么」改成
> **单一权威（本地 Node 代理进程）持有回合状态机，两个窗口只负责渲染与发命令**。
> 一次解决：停止按钮跨窗口无效、僵尸回合、阶梯镜像不一致、双写覆盖、pending 残留。

---

## 一、为什么会"越改越差"（根因）

现状是两个 WKWebView 各自维护一份 React 状态，用三种机制互相猜：

| 机制 | 可靠性 | 现状 |
| :--- | :--- | :--- |
| localStorage（会话/消息） | 共享（默认 data store）✓ | 谁都写 → **后写覆盖**，且是最终态而非实时 |
| BroadcastChannel（`STREAM_*`） | **跨 WKWebView 不保证投递** ✗ | 镜像主要靠它 → 时常不达 |
| `storage` 事件 | 可靠 ✓ | 只用于中止请求与设置 |

于是产生四个结构性问题：

1. **没有仲裁者**："这轮是谁在生成"靠 `abortController` / `isGenerating` 间接推断，
   而 `isGenerating` 在镜像窗口也会置 true（为了显示停止按钮）→ 门禁失效（双写、停止只在本窗口有效）。
2. **命令与状态分离**：点停止的窗口 A 只能"请求"，真正执行在窗口 B；B 若收不到就毫无反应，A 也不知道失败。
3. **收尾路径各自实现**：完成/出错/中止三个出口在两个窗口各写一遍，行为漂移（pending 残留、整轮删除 → 空会话 → 新对话）。
4. **过程状态不可见**：检索/载入阶段没有 token 流，`STREAM_CHUNK` 不发 → 镜像窗口整段检索期什么都收不到。

## 二、目标架构

```
                 ┌──────────────────────────────────────┐
                 │  Node 代理进程（App 启动，常在）      │
                 │  ┌────────────────────────────────┐  │
                 │  │ TurnRegistry（唯一权威）         │  │
                 │  │  turns: Map<turnId, TurnState>  │  │
                 │  │  · 阶段机 rag/prefill/…/done    │  │
                 │  │  · stages[]（阶梯，含耗时）      │  │
                 │  │  · pending / isThinking         │  │
                 │  │  · abort()（直接掐上游请求）     │  │
                 │  └────────────────────────────────┘  │
                 └──▲──────────────┬───────────────────▲─┘
        SSE /turns/stream │      │ POST /turns/:id/abort
                          │      │
             主窗口（纯渲染）│      │浮窗（纯渲染）
             只读 + 发命令   │      │只读 + 发命令
```

- **两个窗口不再有"生成方 / 镜像方"之分**：谁点发送都只是向服务端注册一个回合；
  谁点停止都只是打一个 `abort`，由服务端真正掐断上游（引擎 / 知识库）请求。
- **回合状态只有一份**，窗口只订阅 → 天然一致，不存在双写、僵尸、pending 残留。
- **隐藏/挂起的窗口也不会丢状态**：重新可见时拉一次全量快照即可（SSE 可重连 + `GET /turns` 兜底）。

## 三、状态清单（现状 → 归属）

| # | 状态 | 现在放在哪 | 问题 | 重构后 |
| :-- | :--- | :--- | :--- | :--- |
| 1 | 会话列表 `sessions` | localStorage（两窗口都写） | 后写覆盖 | 保留 localStorage（编辑低频）；**回合内消息由服务端写入** |
| 2 | 当前会话 id | localStorage | 偶发不一致 | 不变 |
| 3 | 设置 `settings` | localStorage + storage 事件 | OK | 不变 |
| 4 | 生成中 `isGenerating` | 各窗口自己的 state | 镜像也会 true → 门禁失效 | 由 `turn.state` 派生（服务端） |
| 5 | 阶段 `stage`（rag/prefill） | 各窗口 + 广播 | 检索期无广播 → 镜像收不到 | 服务端 `turn.stage` |
| 6 | `pending` | 各窗口 + 落盘 | 残留 → 僵尸 | 服务端 `turn.pending` |
| 7 | `isThinking` | 各窗口 + 广播 | 漂移 | 服务端 `turn.isThinking` |
| 8 | 思考/正文内容 | 各窗口累积 + 落盘 | 双份 | 服务端累积，窗口渲染（落盘仍由服务端触发写入） |
| 9 | 阶梯 `stages[]` | 各窗口自记 + 广播 + 落盘 | **双写、互覆盖** | **服务端记录**（知识库阶段本身就在服务端打点，天然权威） |
| 10 | 引用 `citations` | 生成方 + 广播 | 丢失 | 服务端 `turn.citations` |
| 11 | 实时 token `liveStreamingTokens` | 各窗口 | 不一致 | 服务端 `turn.liveTokens` |
| 12 | 指标 `metrics` | 生成方 | — | 服务端 |
| 13 | 中止 | 广播 + localStorage 双通道 | 仅本窗口有效 | `POST /turns/:id/abort`（服务端掐上游） |
| 14 | 知识库服务状态 | 各窗口轮询 | 重复轮询 | 不变（或服务端缓存，后续） |
| 15 | 窗口自身 UI（是否展开、输入框） | 本窗口 | — | **不跨窗口同步**（保持局部） |

> 关键点：**第 9 项阶梯记录搬到服务端是"顺理成章"的** —— 知识库阶段打点本来就在
> 服务端 `wiki_service` 里产生，前端轮询只是"抄一份"；让服务端直接记账可彻底消灭双写。

## 四、分阶段落地（每阶段可独立验收、可独立回退）

### Phase 0 — 冻结基线（0.5h）
- 提交当前工作区为 checkpoint（含未提交改动），打 tag `checkpoint-before-turn-refactor`。
- 冻结：不再往现有镜像链路上打补丁。
- **验收**：`git log` 有 checkpoint；App 行为与现在一致。

### Phase 1 — 服务端回合注册表（权威状态机，生成仍在客户端）
新增 `server/turns.js`（Express 路由，挂到现有代理）：

| 接口 | 说明 |
| :--- | :--- |
| `POST /api/turns` | 开一个回合（sessionId, messageId）→ 返回 turnId |
| `POST /api/turns/:id/state` | **上报**（阶段/stages/pending/isThinking/liveTokens/citations/metrics） |
| `GET /api/turns` | 全量快照（重连/新开窗口用） |
| `GET /api/turns/stream` (SSE) | 增量推送状态变更 |
| `POST /api/turns/:id/abort` | 置 aborted，并**掐断该回合的上游请求**（引擎/知识库） |

客户端改造（两个窗口对称，删掉"生成方/镜像方"分支）：
- 发送：开回合 → 照旧生成，但**把状态变更上报**而非广播。
- 渲染：**一律从服务端状态渲染**（`useTurnState` hook：SSE + 快照）。
- 停止：只调 `abort` 接口，**不再判断本窗口是不是生成方**。
- **验收**：任一窗口点停止都能停；两窗口阶梯/阶段/生成中标记完全一致；检索期切窗口也能看到阶段。

### Phase 2 — 生成过程搬到服务端（真正的"后台维护"）
把 `chatTurn` / SSE 解析 / 知识库检索 / token 估算 移到 `server/`：
- 客户端：`POST /api/chat` 提交一次请求，之后**只订阅 SSE**（token、阶段、阶梯、指标全走同一条流）。
- 客户端删除：`activeStreamsRef`、`STREAM_*` 广播/镜像、`persistSession` 双写、中止分支、
  `requestAbort` localStorage 通道、`STAGES_CHANGED`、`clearStalePending`。
- 服务端写会话落盘（或回调客户端写，二选一，见"待确认"）。
- **验收**：两个窗口代码里再没有 owner/mirror 概念；关掉任一窗口不影响生成；重开即看到进行中的回合。

### Phase 3 — 清理与加固
- 删除 `TurnStageIndicator` 残留、`syncChannel` 里已无用的消息类型。
- 统一"收尾三出口"（完成/出错/中止）为服务端一处：**保留用户提问、只标记回合结束**，永不清空会话。
- 补最小测试：回合状态机的单测（开/上报/中止/结束）+ 两个窗口一致性脚本（已有多份可复用）。
- **验收**：`npm test`（若引入）通过；一致性脚本全绿。

### Phase 4 —（可选）会话也搬到服务端
把 `sessions` 从 localStorage 迁到服务端存储（彻底单一权威，支持"生成中退 App"续跑）。
代价大，建议放最后单独评估。

## 五、风险与回退

| 风险 | 应对 |
| :--- | :--- |
| SSE 在 WKWebView 里断连 | 提供 `GET /api/turns` 全量快照 + 指数退避重连；窗口 focus 时强制拉一次 |
| 服务端状态与 localStorage 会话不一致 | 过渡期（Phase 1）**服务端只管回合状态**，会话仍由客户端写；Phase 2 再统一 |
| 重构期功能回退 | 每阶段独立提交 + tag；任一阶段出问题可 `git revert` 回到 Phase 0 |
| 改动面大 | Phase 1 只新增服务端模块 + 客户端订阅，**不动生成逻辑**，风险最小、收益最大 |
